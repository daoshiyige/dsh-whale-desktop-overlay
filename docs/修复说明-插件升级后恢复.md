# 插件升级后悬浮层消失 —— 原因与恢复

> 适用：`dsh plugin update dsh-whale-widget`（或从插件市场更新）之后，桌面悬浮鲸鱼**整个不见**。

## 一、现在怎么恢复（一条命令）

```bash
node "E:/AI/WB_output/2026-10-06-15-35-13/代码/dshw-desktop-overlay/install.mjs"
```

然后**重启 DSH**。悬浮层会在插件加载时重新挂载。

`install.mjs` 是幂等的：重复跑不会叠加补丁，也不会覆盖你改过的 `config.json`。

## 二、为什么会失效

悬浮层不是独立程序，它靠**改造插件本体**接进来。`dsh plugin update` 会覆盖整个包目录，于是三样东西一起被冲掉：

| 被冲掉的东西 | 作用 |
|---|---|
| `lib/index.js` 里的补丁 A–F | 捕获 `/dsh-whale/*` 原始路由处理器、拉起悬浮层、页内挂件闸门 |
| `lib/desktop-overlay.mjs` | 悬浮层引导（HTTP 服务 + Electron 拉起 + 托盘） |
| `lib/overlay-shell/*` | Electron 主进程、preload、热点窗 |

补丁没了 ⇒ `index.js` 里没有任何代码去 `import('./desktop-overlay.mjs')` ⇒ 悬浮层**不会被启动**。表现就是"完全消失"，不是"出来了但点不动"。

**不受影响**：运行时数据在 `$DSH_HOME/whale-desktop-overlay/` 下（`config.json`、`run/` 日志、私有 Electron 副本），插件更新碰不到。

## 三、0.4.2 带来的第二处变化：新增一个遮罩

新版（v823）加了**泡泡框编辑器**：

```css
.dshwv-framemask{position:fixed;inset:0;z-index:20500;display:flex;...}
.dshwv-framecard{width:560px;max-width:94vw;max-height:92vh;...}
```

它是 `dshwBodyAppend` 挂到 `<body>` 上的 `inset:0` 遮罩，和旧版那 8 个遮罩同一套骨架。
我们的并集靠**显式清单**认遮罩 —— 清单里没有它 ⇒ 卡片进不了并集 ⇒ 热点窗盖不到这个对话框 ⇒ **整个编辑器点不动**（就是以前"菜单点不动"那个 bug 的复现）。

修法：`shell/preload.js` 的清单各补一项。

```js
MASK_SEL += '.dshwv-framemask'
CARD_SEL += '.dshwv-framecard'
```

### 怎么确认"还有没有漏"

挂件源码里有个**权威清单**可对表：算 z-index 的浮层登记表

```js
var getters = [
  function () { return bubbleMask }, ... function () { return frameEditMask }
]
```

以及实际被赋值的类名（`grep "className = '.*mask'"`）。0.4.2 一共 **9 个遮罩**：

```
audiomask  bubmask  confirmmask  cropmask  framemask
gifmask    resmask  snapmask     usage-mask
```

`usagepanel` 仍然是**死 CSS**（有规则、无节点），别加。

## 四、防止下次再漏：场景 18 自动对表

`_selftest/rect-union-test.js` 新增【场景 18】：直接读**真实挂件源码**，把里面每个被创建的 `*mask` 类跟 `MASK_SEL` 对一遍。

```
【场景 18】★ 与真实挂件源码对表：它创建的遮罩必须全在 MASK_SEL 里
    挂件实际创建的遮罩（9）：dshwv-audiomask, dshwv-bubmask, ... , dshwv-usage-mask
  OK   ★ 挂件创建的每个遮罩都在 MASK_SEL 里（漏一个 = 那个对话框点不动）  共 9 个全覆盖
  OK   MASK_SEL 里没有挂件从不创建的幽灵遮罩
  OK   每个遮罩都有对应卡片在 CARD_SEL 里  共 8 对
```

挂件源码路径默认取桌面 profile 下那份，也可用环境变量指定：

```bash
DSHW_WIDGET_ASSET=<path>/assets/whale-widget.js node _selftest/rect-union-test.js
```

找不到源码时该场景**跳过而不报错**（换机器不会假失败）。

**以后升级插件的标准动作**：

```bash
node install.mjs && node _selftest/rect-union-test.js
```

场景 18 如果报"缺：dshwv-xxxmask"，就是新版又加了对话框，照着补 `MASK_SEL` / `CARD_SEL` 即可。

## 五、其它曾经踩过的同类坑

| 位置 | 教训 |
|---|---|
| `MASK_SEL` / `CARD_SEL` | 静态清单会随插件升级过期 —— 现在有场景 18 兜底 |
| `PANEL_SEL` | `tplhelp` 曾经漏过（body 挂载的提示层，点它能关） |
| 判定点层级 | 「页内挂件」开关曾经判在"宿主启动时一次性收集注入表"那一层 ⇒ 改配置刷新无效（已改为请求时判定，patch-F） |
| 死 CSS | `.dshwv-usagepanel` 有完整规则但无节点；往清单加之前先确认元素真被创建 |
