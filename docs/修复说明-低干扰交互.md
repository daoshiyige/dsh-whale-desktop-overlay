# 低干扰交互模式修复说明

基线：`48b44f8`（用户确认的初始版本）
分支：`fix/hot-menu-click`
改动：`shell/main.js` + `shell/preload.js`（共 189 行新增）

---

## 一、你报的两个症状，根因是什么

### 症状 ①：低干扰模式下菜单/设置面板点不动

面板 `.dshwv-menu` **不是**鲸鱼 `.dshwv-root` 的子节点，而是用
`document.body.appendChild()` 挂到 `body` 上的（挂件源码 `whale-widget.js`
第 11905 行 `dshwBodyAppend(menuBox)`）。

而初始版的 `interactiveRect()` **只扫 `.dshwv-root` 子树**：

```js
root = document.querySelector('.dshwv-root')
nodes = root.querySelectorAll('*')     // 面板根本不在这棵树里
```

面板用 `position:fixed` 定位，鲸鱼贴在屏幕右下角时它**必然向上展开**，
整体落在鲸鱼包围盒之外。热点窗只盖鲸鱼 → 面板那一片区域
**没有任何窗口接收鼠标** → 点不动。

实测几何（1707×1019 工作区）：

```
面板      y = 565 ~ 865
鲸鱼      y = 769 ~ 1019
热点窗    y = 755 ~ 1033     ← 面板顶部 190px 落在窗口之外
```

### 症状 ②：鼠标在鲸鱼上移动时光标在箭头 ⇄ 手型之间跳

`.dshwv-root` 带 CSS 过渡：

```css
.dshwv-root{ transition: left .16s ease, top .16s ease, transform .3s ease }
```

**过渡进行中 `getBoundingClientRect()` 返回的是插值位置**（正在移动中的坐标）。
初始版的 `applyHotRect()` 用「完全相等」判断要不要重新定位：

```js
if (prev.x === b.x && prev.y === b.y && prev.width === b.width && ...) return
```

于是每个 200ms 采样点都判定为"变了" → 每个采样点都调一次 `setBounds` 挪窗口。
**在光标正下方反复挪窗口**，系统会不断给热点窗补发进入/离开事件，
页面因此反复清掉又重建 hover 态 → 光标在 `grab`（手型）和默认箭头之间跳。

日志实证：`shell.log` 里有 **46 条**「热点窗定位」，`h` 在 147~156 之间来回摆。

## 二、改了什么

### `shell/main.js` —— 热点窗定位加阈值（提交 `e8a318a`）

把「完全相等」换成「位置/尺寸分别判 10px 阈值」，锚点是**上一次真正应用的**
`hotState.bounds`：

```js
const HOT_POS_EPS = 10
const HOT_SIZE_EPS = 10

const posSame  = |b.x - prev.x| <= 10 && |b.y - prev.y| <= 10
const sizeSame = |b.width - prev.width| <= 10 && |b.height - prev.height| <= 10
if (posSame && sizeSame) return          // 窗口一动不动
```

阈值取 10px 的依据：实测过渡抖动 ≤7px，真实变化是几百 px（菜单开合）
或几十 px（拖动），中间空档很大，10px 落在里面不会误伤。

**实测效果**（拿 `shell.log` 里真实的 46 条矩形序列回放）：

| | setBounds 次数 |
|---|---|
| 初始版 | 46 |
| 修复版 | 32（降 30%）|

被消掉的正是 `204x182 ⇄ 203x183` 这类 ±1~2px 抖动；
`282x269` / `274x483` 这类真实变化（菜单开合）**照常跟随**。

### `shell/preload.js` —— 并集逻辑重写（提交 `4fb2daf`）

**核心思路：几何即真相，单通路上报。**

| 新增函数 | 作用 |
|---|---|
| `rootBox(root)` | 鲸鱼落点盒 = 内联 `style.left/top`（**过渡目标值**，稳定）+ `offsetWidth/Height`（布局值，不受过渡影响）。**绝不读过渡中的 rect** |
| `OVERLAY_SEL` | 显式弹出层类名清单（8 个遮罩 + 面板 + 列表），逐个量可见的并入并集 |
| `popupRect(el)` | 只认 `display !== 'none'`；opacity 要求 `>= 0.9`（过渡中途 0.4 不算「开着」）|
| `effectiveOpacity(el)` | 沿祖先链**累乘** opacity —— CSS opacity 不继承，子元素自身恒为 1，只看自身会把「父层已淡出」的层误判为可见 |
| `stabilizeRect(r)` | 页面侧死区（位移 6px / 尺寸 24px）|

`interactiveRect()` 现在是：**① 鲸鱼落点盒 ∪ ② 所有可见弹出层**。
**不再扫 root 子树**。

面板几何由第 ② 步直接保证 → 面板必然被盖住，且**没有时序竞态**
（不依赖「抢在面板弹出那一瞬扩窗」）。

## 三、两条已经走过的弯路（别再走）

1. **扫 `.dshwv-root` 整棵子树**
   子树里全是会动的装饰（呼吸动画、hover 悬浮、菜单按钮）。
   实测会把并集炸到 **1607×919 ≈ 整个视口**，而且每 200ms 都在变 → 窗口狂抖。

2. **只扫 root + 用 `expanded` 让路机制兜面板**
   抖动治好了，但面板点不动；更糟的是 `expanded` 是
   「本页先置位 → 主进程再扩窗」的两段式，**一旦主进程错过/拒绝扩窗**
   （拖动打断、`setBounds` 失败），本页 `reportRect` 就**永久让路** →
   热点窗永久停在旧位置 → **连鲸鱼都点不动**。

本次直接**取消 `expanded` 让路**，失败态从根上不存在。

## 四、两级过滤

```
页面侧 stabilizeRect   (6px / 24px)
        ↓
主进程 HOT_POS_EPS     (10px)
        ↓
setBounds
```

两层都要有：页面侧挡采样噪声，主进程侧挡窗口取整/过渡噪声。

---

## 五、怎么验证

重启 DSH 后确认三件事：

1. **光标不跳**：鼠标在鲸鱼区域移动，光标稳定保持手型（`grab`），停下仍是手型
2. **面板能点**：点菜单按钮打开设置面板，面板上的选项**全部**可点（尤其面板顶部）
3. **拖动正常**：能拖动鲸鱼，松手后热点窗正确吸附

出问题时看：
- 日志：`<DSH_HOME>/whale-desktop-overlay/run/shell.log`
- 状态：`<DSH_HOME>/whale-desktop-overlay/run/shell-status.json`
- 托盘右键 → 取消「低干扰交互」可退回旧的 `window` 模式对照

## 六、离线自测

```
node _selftest/rect-union-test.js        # 8 场景 31 断言
node _selftest/hot-stability-test.js     # 9 场景 15 断言
```

两个都全绿。关键断言：

- 面板开 → 并集顶边从 769 延伸到 **565**，面板顶到鲸鱼顶这 **204px 全被覆盖**
- 面板关 → 并集恒等于鲸鱼落点盒 250×250
- 回归：子树里塞 2000×2000 装饰，并集仍是 250×250（不再炸全视口）
- ±9px 噪声经两级过滤后只应用 1 次

> 注：`selftest.mjs`（在线渲染自检）在本机跑不起来，与本次改动无关 ——
> 它故意用 `disableGpu:false`，会触发 GPU 崩溃循环；而且它的临时目录清理
> 被本环境的回收站机制拦截，连启动都到不了。已用原始版本对照确认。
