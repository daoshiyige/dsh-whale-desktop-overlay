# 修复说明：托盘「DSH 页面里也显示小鲸鱼」勾了没反应

> 提交：`81348da`
> 涉及文件：`install.mjs`（补丁 D 改判 / 新增补丁 F）、`overlay.mjs`（请求标记头）

---

## 一、症状

托盘右键 → 勾上「DSH 页面里也显示小鲸鱼」→ **DSH 页面上没有出现第二只鲸鱼**。
取消勾选、刷新页面，同样没有任何变化。

---

## 二、根因：判定点选错了层级

这个开关原本判在**「往宿主的页面注入表里推不推这一行」**那里（补丁 D）：

```js
// 旧 patch-D
if (__dshwInAppWidgetDisabled()) return
```

问题在于这一层被调用的时机 —— 插件源码里写得很清楚：

> 桌面端的注入表是**宿主启动时一次性收集**的
> （`dsh-desktop-host`：`collectIndexInjections()` → IPC → 渲染层），
> 订阅一旦晚于那次收集，这一行就永远进不了表。

所以这条 `return` **只在 DSH 启动那一刻执行一次**：

| 时刻 | 配置 | 结果 |
|---|---|---|
| DSH 启动 | `hideInAppWidget: true` | 这一行**没进表** |
| 之后勾上开关 | `false` | 表已经定了，**永远不会变** |
| 刷新页面 / 重启悬浮窗 | `false` | 还是那张表，**依然没有** |

⇒ 只有**重启 DSH** 才可能变。而托盘文案写的是「刷新 DSH 页面后生效」，是错的。

### 为什么浏览器里没这个问题

Web 形态走的是另一条通道 `tapIndex`（补丁 E）—— 它是**每个 HTTP 请求**都过的，
所以浏览器里「勾上 → 刷新」确实生效。桌面壳不走 `tapIndex`
（它的 `index.html` 是从安装包静态 dist 直出，永不经过 `renderIndex()`），
所以这个 bug **只在官方桌面端复现**。

### 顺带查清的一件事：overlay 窗口加载的不是 DSH 页面

调试时容易误判「桌面那只也算页内挂件」，其实不是。抓一次真实响应就清楚了：

```
$ curl 'http://127.0.0.1:37917/?t=<token>'
<!doctype html>
<title>DS Whale Desktop Overlay</title>      ← overlay.mjs:195 生成的极简页
...
<script src="/dsh-whale/widget.js"></script>  ← 只引这一个脚本
```

悬浮层跑的是 `overlay.mjs` 起的**独立 HTTP 服务**（监听 `config.port`），
首页是它自己拼的一张透明页，`/dsh-whale/*` 则分发给插件已注册的原始 handler。
**所以 `hideInAppWidget` 只管 DSH 页面，跟桌面那只无关。**

---

## 三、修法

把判定从「收集注入表的那一层」挪到「每次请求都会过的那一层」。

| 补丁 | 变化 |
|---|---|
| **D**（`webserver/index-inject`） | 删掉短路 → **永远把这一行推进注入表**（只留注释说明原因） |
| **F**（新增，`/dsh-whale/widget.js` 路由） | 在这里按请求判 `hideInAppWidget` |

选这条路由当判定点，是因为它**本来就带 `Cache-Control: no-store`** ——
页面每次加载都会重新请求它，所以「勾选/取消 → 刷新页面」立刻生效，不用重启 DSH。

### 关键难点：不能把桌面那只一起拦掉

桌面那只也是通过同一条路由拿 `widget.js` 的。如果在路由里无差别地拦，
`hideInAppWidget: true` 时**桌面鲸鱼会跟着消失**。

解法是给请求打标记。悬浮层的服务在分发到插件路由前加一行：

```js
// overlay.mjs
try { req.headers['x-dshw-overlay'] = '1' } catch (err) {}
```

补丁 F 据此放行：

```js
if (__dshwInAppWidgetDisabled() && !__dshwIsOverlayRequest(req)) {
  res.writeHead(200, { 'Content-Type': 'application/javascript; charset=utf-8', 'Cache-Control': 'no-store' })
  res.end('/* dshw-desktop-overlay: 页内挂件已关闭 */\n')
  return
}
```

三个细节都是故意的：

| 细节 | 原因 |
|---|---|
| **拿不到 `req` / `headers` 时按「悬浮层」处理**（返回 `true`） | fail-safe 方向选「不拦」。宁可少拦一次（页内多一只），**绝不能把桌面那只弄没** |
| 拦截时回 **200 + 合法 JS 注释**，不回 404 | 脚本的 `onerror` 不触发，控制台干净 |
| 拦截时也带 `no-store` | 否则空响应被缓存住，开关「开回来」会失效 |

## 四、验证

`_selftest/inapp-widget-test.js` —— **8 场景 40 断言全绿**：

- ★ 闸门真值表（配置 × 来源 四种组合）
- ★ 拿不到 `req` / `headers` 时一律放行（4 个边界用例）
- ★ **直接执行部署后的 patch-F 代码块**（不只是看条件表达式）：
  - 拦截路径确实 `return`（没继续走到 `loadWidgetJs()`）
  - 回 200、`Content-Type: application/javascript`、`no-store`、body 是 JS 注释
  - 悬浮层请求放行、未提前结束响应
- ★ patch-D 里不许再出现 `__dshwInAppWidgetDisabled()` 或任何可执行 `return`
- ★ patch-F 紧跟 `/dsh-whale/widget.js` 路由声明（位置断言）
- ★ `overlay.mjs` 的标记头设置在 `route.handler(req, res)` **之前**
- ★ 六段补丁各只有一份；`stripBlocks` 正则覆盖到 `A-F`（否则重装会叠加）

另：连续执行两次 `install.mjs`，六段补丁计数仍全是 1（幂等）。

全套：**rect-union 66 + hot-stability 15 + autoreload 24 + inapp-widget 40 = 145 断言 0 失败。**

## 五、生效方式（重要）

补丁写在插件的 `lib/index.js` 里，**只在插件加载时读取**。所以：

- **第一次需要重启一次 DSH**，让新补丁进内存；
- 之后「勾选/取消 → 刷新 DSH 页面」**即时生效**，不用再重启。

## 六、一个仍然存在的设计问题（未改）

`hideInAppWidget: false` 时，DSH 页内会出现一只鲸鱼，
而桌面悬浮层**仍然在同一个位置画一只、并且热点窗照样吃鼠标**。
两只位置几乎重合，看起来像一只，点击落在悬浮层的副本上（能用，但不是页内那只）。

如果你想要的是「只在 DSH 页面里显示、不要浮在桌面上」，
正确的组合是 **`enabled: false`（关掉悬浮层）+ `hideInAppWidget: false`** ——
此时页内那只独占输入，不会被抢。

要改成「勾上页内挂件时悬浮层自动让位」，需要动 `main.js` 的输入模式切换，
属于行为变更，需要单独确认。
